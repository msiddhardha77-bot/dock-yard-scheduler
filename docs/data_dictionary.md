# Data dictionary

All identifiers are integer surrogate primary keys unless a business `code`, `reference`, or `event_reference` is marked unique. Timestamps are UTC internally. CSV exports are generated by `scripts/export_data.py`.

| Entity / field | Type | Required / key | Allowed values / validation | Relationship / derivation |
|---|---|---|---|---|
| `facilities.id`, `code`, `name`, `timezone`, operating times, `yard_capacity` | integer/string/time | required; id PK, code unique | capacity ≥ 0; operating end after start | parent of docks, zones, slots, appointments |
| `docks.id`, `facility_id`, `code`, `dock_type`, capability flags, `vehicle_types` | integer/string/boolean | required; id PK; facility+code unique | inbound/outbound flags; active only | N:1 facility; reservation target |
| `yard_zones.id`, `facility_id`, `code`, `capacity` | integer/string | required; facility+code unique | capacity ≥ 0 | N:1 facility |
| `yard_slots.id`, `facility_id`, `code`, `capacity`, `slot_type`, `active` | integer/string/boolean | required; facility+code unique | capacity ≥ 1 | N:1 facility; additive slot master |
| `carriers.id`, `code`, `name` | integer/string | required; code unique | stable carrier code | parent of vehicles/drivers |
| `vehicles.id`, `carrier_id`, `registration`, `vehicle_type`, `capacity_kg` | integer/string | required; registration unique | capacity > 0 | N:1 carrier; shipment reference |
| `labor_shifts.id`, facility, name, start/end, workers | integer/time | required | workers ≥ 0 | N:1 facility; assignments |
| `handling_requirements.id`, `shipment_id`, refrigerated/hazardous, workers, service minutes | integer/boolean | required; shipment unique | service minutes > 0 | 1:1 shipment; source of special compatibility |
| `shipments.id`, `reference`, facility/carrier/vehicle, direction, weight | integer/string | required; reference unique | direction `INBOUND`/`OUTBOUND`; weight ≥ 0 | 1:N appointments in schema intent; current UI uses one appointment per shipment |
| `appointments.id`, `reference`, shipment/facility, requested/scheduled windows, duration, status | integer/string/datetime | required; reference unique; window and duration checks | `REQUESTED`, `SCHEDULED`, `CHECKED_IN`, `AT_DOCK`, `IN_SERVICE`, `COMPLETED`, `DEPARTED`, `CANCELLED`, `REJECTED`, `NO_SHOW` | N:1 shipment/facility; parent of events/exceptions/reservations |
| `check_in_events.id`, `event_reference`, appointment, attempt, attempted time, outcome/reason | integer/string/datetime | required; reference unique; appointment+attempt unique | `ACCEPTED`/`REJECTED`; reason code | N:1 appointment; append-only attempts |
| `gate_visits.id`, appointment, check-in/out times | integer/datetime | appointment unique | checkout after completion | operational visit record |
| `lifecycle_events.id`, appointment, from/to status, type, event time | integer/string/datetime | required; id PK | transitions validated by lifecycle service | append-only N:1 appointment |
| `dock_reservations.id`, dock/appointment, start/end, status | integer/datetime | required | `ACTIVE`/`CANCELLED`/`COMPLETED`; end after start | N:1 dock and appointment; historical rows are retained; overlap checked by service |
| `labor_assignments.id`, shift/appointment, workers | integer | required | workers > 0 | bridge between labor and appointments |
| `yard_occupancy.id`, facility/appointment, entry/exit | integer/datetime | required | exit after entry when present | operational capacity evidence |
| `yard_slot_reservations.id`, yard slot/appointment, start/end, status | integer/datetime/string | required | `ACTIVE`/`CANCELLED`; end after start | interval reservation used for yard utilization |
| `appointment_timelines.id`, appointment, actual arrival, yard entry, dock arrival, service start/end, departure | integer/datetime | appointment required; one timeline per appointment | endpoint pairs are required for derived durations; null means unavailable | event-derived metric source |
| `operational_exceptions.id`, appointment/facility, severity, cause, description, resolution fields | integer/string/datetime | facility/severity/cause/description required | status `OPEN`/`RESOLVED` | N:1 appointment/facility |
| `scheduling_decisions.id`, appointment, decision, reason code, details | integer/JSON | required | accepted/rejected; centralized reason codes | audit record for scheduler |
| `anomaly_labels`, `ground_truth_records` | integer/string/JSON | required | separate synthetic evaluation labels | not used as scheduling input |

The required domain additions are additive and do not rename existing tables. Existing databases should run `flask init-db` for new tables and apply documented migrations for column changes.

## Complete field definitions for previously omitted entities

The following entries are verified against `app/models/masters.py` and
`app/models/events.py`. `DATETIME` values are stored/handled as UTC by the
application. SQLite and MySQL physical type names may vary through SQLAlchemy,
but the logical types below are the model types.

### `drivers`

| Field | Type / unit | Required | Key / uniqueness | Allowed values and validation | Relationship |
|---|---|---|---|---|---|
| `id` | integer | yes | primary key | surrogate identifier | — |
| `carrier_id` | integer | yes | foreign key | must reference `carriers.id` | N:1 carrier |
| `name` | string(120) | yes | — | no model enum or check constraint | driver name |
| `license_number` | string(50) | yes | unique | no model enum or check constraint | business identifier |

`drivers` has no optional fields and no application-defined unit-bearing
values. The model defines the carrier foreign key and unique license number;
it does not define a cascade or a driver-status enum.

### `simulation_runs`

| Field | Type / unit | Required | Key / uniqueness | Allowed values and validation | Relationship |
|---|---|---|---|---|---|
| `id` | integer | yes | primary key | surrogate identifier | — |
| `seed` | integer; deterministic seed, unitless | yes | — | any integer accepted by the model | identifies a simulation/generation input |
| `mode` | string(20) | yes | — | generator modes are `starter`, `medium`, and `full`; the model itself has no SQL enum/check | generation/simulation mode |
| `started_at` | datetime; UTC | yes | — | application default is current UTC time | run start timestamp |
| `completed_at` | datetime; UTC | no | — | nullable until completion | run completion timestamp |
| `manifest` | JSON | no | — | nullable; application default is an empty mapping when created through the model | run metadata; no FK |

The model does not declare a unique constraint on `(seed, mode)`. Generator
idempotency checks that pair in application code through `SimulationRun`.

### `ground_truth_records`

| Field | Type / unit | Required | Key / uniqueness | Allowed values and validation | Relationship |
|---|---|---|---|---|---|
| `id` | integer | yes | primary key | surrogate identifier | — |
| `entity_type` | string(40) | yes | — | application-defined entity label; no SQL enum/check | identifies the evaluated entity class |
| `entity_id` | integer | yes | — | application-defined entity identifier; no SQL FK by design | generic reference paired with `entity_type` |
| `truth` | JSON | yes | — | structured ground-truth payload; no SQL shape constraint | evaluation evidence, not scheduling input |

`ground_truth_records.entity_id` is intentionally not a foreign key because
ground truth can describe more than one entity type. The current generator
uses appointment-level ground truth and stores the corresponding issue type,
label, and scenario evidence in `truth`.
